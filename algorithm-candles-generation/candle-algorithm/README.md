# candle-algorithm

Price and candle generator for a **trading game**. Every market is fictional,
every price is generated by a model, and stakes are **hamoud**: in-game coins
with no cash value. Nothing is paid out; a trade only ends as WIN or LOSS. The
demo page shows a notice saying all of this before the game starts, keeps a
"SIMULATED GAME" banner on screen, and watermarks the chart.

The prices are fake, but the behaviour is calibrated on real markets, so the
charts look right (see [How realistic is it](#how-realistic-is-it)).

## Install

From this folder:

```bash
npm install
```

## Run

Game demo in the browser, all 19 markets live:

```bash
npm run live        # → http://localhost:5180
```

Fast demo — no waiting, prints two hours of candles for one market instantly:

```bash
npm run example:fast
MARKET=NOGE-BUKT MINUTES=240 SEED=7 npm run example:fast
MODEL=garch npm run example:fast       # the original model, for comparison
```

Realism benchmark — simulates every market and compares it with real data
(downloads public 1m/5m bars from Binance and Yahoo Finance once, caches them in
`.realism-cache/`):

```bash
npm run realism
MARKET=BOT-BUKT DAYS=28 npm run realism
MODEL=garch npm run realism
```

Live-cadence demo (ticks every `TICK_DT_SEC` real seconds) and the steering demo:

```bash
npm run example
npm run example:magnet
```

Type-check only:

```bash
npm run typecheck
```

## The live demo

`live/server.ts` runs one `AssetRegistry` per market and streams the market
you're looking at over Server-Sent Events (`candles:history` / `candle:close`
/ `tick`), plus a `quotes` message twice a second for the market list. The page
(`live/client.ts`) folds them with `applyChartMessage` and draws them with
TradingView's lightweight-charts 5.2.1.

- **Notice screen** on first load each browser session, re-openable from the
  banner. Edit the text in `live/index.html`.
- **Markets** — pick one from the list; the URL hash (`#BOT-BUKT`) remembers it.
- **Trade** — 30s / 60s / 2m, stake 10–500 hamoud, UP or DOWN.
- **Game settings → Win rate** 25% / 50% / 100%, and **Show game internals**
  (planned result, target line, steering).
- **Speed** 1× / 10× / 60× / 300× chart seconds per real second, **Pause** +
  **Step 1 tick**, **Skip ahead** +15m / +1h / +6h, **Restart**.
- **Price model** — Realistic (MSM) or Classic (GARCH), to compare.
- **trendPersistenceSec** slider — momentum (body vs wick).
- **Timeframe** 1m / 5m / 15m / 1h.

`PORT`, `SEED` and `HISTORY_MINUTES` (default 720 — history generated for every
market at start-up and on each rebuild, ~2.5 s for 12 h) env vars override the
defaults.

## The markets

All in `src/markets.ts`. The names are made up so nobody mistakes them for a
real instrument; starting prices are round numbers. Rename freely — only `id`
must stay stable.

| Group | Markets |
|-------|---------|
| Currencies | ROO/BUK, YUR/BUK, QID/BUK, BUK/MOO, BUK/CHZ, BUK/NEK |
| Metals | FOOL'S GOLD |
| Indices (fictional Shiftyland exchange) | RANK SHIFTY, FUN SHIFTY, SHIFTY 50, SHIFTY IT, SHIFTY MIDCAT 100, NONSENSEX |
| Crypto (quoted in BUKT) | BOT, MEH, BBQ, LOL, NOGE, BURP |

Each market has its own volatility (`sigma`), tail strength (`m0`) and
time-of-day profile, measured on a comparable real instrument in Oct 2026.
`realism.ts` holds that mapping.

## What goes into one tick

Every tick (one chart second in the demo) the engine:

1. **Updates volatility.** Three pieces multiply:
   - **MSM** (`src/msm.ts`) — Markov-switching multifractal volatility (Calvet
     & Fisher). Eight layers, each `m0` or `2 − m0`, re-drawn now and then: the
     slowest about every 3 days, the fastest every second. Calm and busy
     spells nest inside each other on every time scale, which gives real
     markets' fat tails and long volatility memory.
   - **Time of day** (`src/intraday.ts`) — 24 hourly multipliers measured on
     real data: currencies peak at the London/New York overlap, crypto at the
     US open, indices at their session open.
   - **News shocks** (`src/news.ts`) — about 1.5 a day, a surge to ~5× normal
     volatility that fades over ~10 minutes. Added in variance, and the whole
     thing is rescaled so daily volatility stays calibrated.
   The volatility state never looks at the price, so the shown and honest
   paths share it. With `model: "garch"` a GARCH(1,1) (`src/garch.ts`) is used
   instead.
2. **Draws a shock.** `createRng(seed).normal()` returns a standard normal `z`.
3. **Composes the move** in log space (`src/step.ts`), then clamps it:

   | Layer | What it does |
   |-------|--------------|
   | L1 base   | volatility × shock, with short-term momentum (`trendPersistenceSec`) — the honest random walk |
   | L2 drift  | small bounded bias (0 in the demo) |
   | L3 magnet | game steering toward a trade's `targetPrice` |
   | L4 anchor | weak pull toward an outside reference price (0 in the demo) |
   | L5 self-anchor | pull toward the asset's own honest path (0 in the demo) |

4. **Records the SHOWN price into every timeframe's candle**
   (`CandleAggregator.addTick`, `src/candles.ts`) after any commit snap, so no
   closed bar carries a high or low the live chart never drew.
5. **Broadcasts** a `tick`, and a `candle:close` whenever a bucket closes.

## How realistic is it

`npm run realism` (14 simulated days per market vs the real counterpart; sim /
real) — a sample:

| Market | vol/day % | tails, bar | tails, 1h | vol memory, 1 bar | body % |
|--------|-----------|------------|-----------|-------------------|--------|
| YUR/BUK (5m) | 0.32 / 0.31 | 46.9 / 22.1 | 6.6 / 10.9 | 0.37 / 0.24 | 53 / — |
| BOT/BUKT (1m) | 1.77 / 1.61 | 26.5 / 11.9 | 4.7 / 7.9 | 0.39 / 0.35 | 62 / 69 |
| NOGE/BUKT (1m) | 3.43 / 3.19 | 24.0 / 25.0 | 8.5 / 14.0 | 0.40 / 0.31 | 63 / 55 |
| same, original GARCH | 1.81 / 1.61 | 1.8 / 11.9 | 0.1 / 7.9 | 0.07 / 0.35 | 70 / 69 |

"Tails" is excess kurtosis (0 for a bell curve); "vol memory" is the
autocorrelation of |return|. The original GARCH model had essentially no fat
tails, no volatility memory and no daily rhythm, which is why its charts read
as even noise. Single tail numbers swing a lot between seeds and between
two-week windows of real data, so compare ranges rather than exact values.

## Game steering

`src/magnet.ts` and `src/path-style.ts` steer the chart toward a trade's
`targetPrice` so the result matches the one the game picked when the trade
opened (Win rate setting). The demo shows this openly: with **Show game
internals** on, each position lists its planned result and path style, the
chart draws the target line, and the tick panel shows the pull.

Three shapes decide HOW the chart travels:

- **DIRECT** — ramps smoothly toward the target from the start.
- **OSCILLATE** — small sine around entry for 60% of the trade, then
  smoothstep convergence over the remaining 40%.
- **FEINT** — first 35% drives AWAY from the target, then reverses and
  converges. Only picked for trades > 20s.

Four pieces decide HOW MUCH it pulls each tick:

1. `pathBias(style, elapsedFrac)` — a scalar in roughly [-1, +1].
2. `blendedMagnet(trades, currentPrice, nowSec, sigmaTick)` — open trades vote
   with their stake (hamoud) for a log-space direction, clamped to
   ±`MAGNET_CAP·sigmaTick`.
3. **Tightening** — inside the last `MAGNET_WINDOW_SEC` the pull ramps up to 2×.
4. `commitSnap(shownPrice, trades, nowSec, tickSize)` — in the last
   `COMMIT_WINDOW_SEC` the shown price is eased toward the target, at most
   `tickSize × MAX_COMMIT_SNAP_MOVE_TICKS` per tick. Because the budget is in
   ticks, it is strong on markets with tiny ticks relative to their
   volatility (currencies) and weak on others (crypto). A trade the budget
   can't rescue settles on wherever the chart ends — the page flags it as
   "steering missed".

The demo places the target `TARGET_SIGMAS` (0.35) standard deviations of the
trade-length move from entry.

## Timeframes

1m is the primary timeframe. 5m / 15m / 1h each have their own aggregator per
market; `resample(...)` in `src/candles.ts` can also build them from 1m candles.

## Working on the algorithm

- Per-market behaviour: `sigma`, `m0` and `intraday` in `src/markets.ts`.
- Shared MSM shape: `marketMsm` (layers, fastest/slowest timescales).
- News shocks: `MARKET_NEWS` in `src/markets.ts`.
- Body vs wick: `trendPersistenceSec` (4 s default with MSM ≈ 62% body on 1m).
- After any change, run `npm run realism` to see how far each market drifts
  from its real counterpart.
